# Инструкция для Claude Code — Analysis-Software-v2

## Проект

**Автоматизированная система построения цифровых карт безопасности** — desktop-приложение (Python 3.13 + Tkinter + CustomTkinter) для построения топологии сети, разложения узлов по уровням модели УБИ и расчёта маршрутов распространения угроз.

Разрабатывается как дипломная работа. Эталоны, по которым строится модель, лежат в `Promts/СХЕМЫ, ИСХОДНИКИ, ДАННЫЕ` (папка в .gitignore — переносить отдельно).

## Предметная модель — расшифровка терминов

Без этого код не читается.

| Термин | Расшифровка | Что это в программе |
|---|---|---|
| **РИС** | Распределённая информационная система | Вся схема на холсте |
| **ТИМ** | Типовой информационный модуль | Зоны: ТИМ-1 ЛВС, ТИМ-2 ЦОД, ТИМ-3 удалённый пользователь |
| **УБИ** | Угроза безопасности информации | То, что распространяется по графу |
| **ДВ** | Деструктивное воздействие | «Объект ДВ» — компонент, по которому бьют |
| **ПКА / ККА** | Простая / комплексная компьютерная атака | ККА = цепочка из 4 ПКА (этапов) |
| **ЦО / ТрО** | Целевой / транзитный объект | Роль вершины графа: цель или транзит |
| **ω** (омега) | Точка входа УБИ | Физический порт узла |
| **χ** (хи) | Маршрут распространения УБИ | `χ3.5` = третий маршрут, пятый шаг |
| **α** (альфа) | Этап ККА | α1…α4 — четыре этапа атаки |
| **ЭМВОС** | Эталонная модель взаимодействия открытых систем | Это OSI по-русски, ГОСТ Р ИСО/МЭК 7498-1-99 |

### Уровни и их буквенные коды

Внешний каркас — 4 уровня модели УБИ ФСТЭК, внутрь них вложены уровни ЭМВОС:

```
Пользовательский   h — периферия
Прикладной         q — прикладной ЭМВОС · r — представления · d — сеансовый
Системный          t — транспортный · l — сетевой · z — канальный
                   i — драйверы · w — доступ · p — файлы · v — процессы
Аппаратный         f — физический ЭМВОС и точки входа ω · а — железо
```

Коды используются для подбора профиля фильтрации CVE — см. `level_code_for()`.

**Внимание:** в `models/threat_graph.py` у `LEVEL_PREFIXES` аппаратный уровень
помечен `h`, а пользовательский `u` — это расходится с паспортом. Для подбора
профилей есть отдельный корректный словарь `GRAPH_LEVEL_CODES`.

## Как ищутся уязвимости

```
компонент
  → extract_cpe_components() или get_protocol_cpe()   {vendor, product, version}
  → CVEDatabase.get_cves_for_component()              полная выборка по CPE
  → filter_cves_by_level(level_code, component_name)  отбор по уровню  ← ключевое
  → BDUDatabase.get_many_by_cve()                     русское описание, эксплойт
  → assess_component(bdu_records=...)                 V по методике ФСТЭК
```

**Почему нужен фильтр по уровню.** CPE указывает на продукт, а не на компонент
внутри него. У `microsoft/windows` 17 611 CVE обо всём подряд, поэтому без
второго фильтра в строку «TCP» попадали Samba и пустые пароли администратора.
Профили уровней — в `utils/level_filter.py`.

**Пустая ячейка CVE — нормальный результат.** В эталонном паспорте у большинства
строк прочерк.

## Состояние работ

### Сделано и видно в интерфейсе
- Фильтр CVE по уровням — паспорт, схема ЭМВОС, граф угроз
- Колонки «Реестр» и «БДУ ФСТЭК» в паспорте, экспорт в PDF пересчитан
- Расчёт V по методике: показатель E из БДУ, все 12 значений H, сроки устранения
- ЦО/ТрО в графе угроз — структурное свойство, а не «нашлись CVE»

- **Окно «Маршруты УБИ»** (`views/kka_view.py`) — кнопка в разделе АНАЛИЗ.
  Три панели: цели по критичности, поле волны, развёрнутый маршрут.
  Вектор ККА из четырёх этапов строится автоматически
- Автоподбор целей этапов (`models/kka.py`) — профили CWE со схемы Shablon_atak

### Основа без собственного интерфейса
- `models/topology_graph.py` — граф всей топологии (435 вершин на 8 узлов за 3 мс)
- `models/wave.py` — волновой алгоритм с подсчётом маршрутов и критическим путём

### Не начато
- Маркеры χ на схеме ЭМВОС
- Матрёшка схем: РИС → ТИМ → узел → уровень → компонент → уязвимость
- Дозагрузка CAPEC Categories (в базе 615 записей и ни одной Category —
  отсутствуют CAPEC-118, 255, 152, 225, вершины цепочек α1…α4)
- Признак «критичные бизнес-процессы» у узла (K = 1,1 по таблице 1 Методики).
  Без него сервер с защищаемыми данными не выделяется по критичности:
  у сетевых устройств коэффициент 0,9, а у серверов 0,7

## Правила работы

- Общение на русском языке
- Инкрементальный подход: каждый шаг показывать и подтверждать
- Релизы, коммиты и теги — только по явной просьбе
- Python 3.13: всегда оборачивать `after()` в try/except, использовать queue
  для фоновых потоков
- Проверять изменения запуском `main.py`, а не только импортом

## Известные проблемы

- Python 3.13 `deletecommand` crash — косметический
- Маршрут делает лишний шаг `порт → IEEE 802.3 → порт` внутри транзитного узла —
  артефакт зернистости модели, на достижимость не влияет
- В `bdu_fstec.db` колонки импорта названы неверно: `fix_status` содержит наличие
  эксплойта, `exploit` — статус уязвимости, `impact` — способ устранения.
  `database/bdu_db.py` отдаёт записи уже с правильными именами
- `smart_search_cves` существует, но не используется — тяжёлый
- Тестов нет
